# Spec notes

Places where the brief, the UI spec and the API disagree or leave a gap, and what we decided.
Type: `conflict` (two sources disagree) · `gap` (design shows something the API can't provide) · `risk` (easy to get wrong).

| ID | Type | Note | Decision |
|---|---|---|---|
| N-001 | conflict | The colour page says text on primary is always white; the dark-theme `onPrimary` token is `#10202a`. Dark screens show white text on teal buttons | Follow the screens: white text on primary in both themes |
| N-002 | gap | The receipt shows reference, date and new balance; the transfer and bill-payment responses contain none of them | Resolve the new transaction from the account history and load it by id ([ADR-0008](decisions/0008-receipt-resolution.md)) |
| N-003 | conflict | The API has six account types; the design shows Savings, Checking and Money market | Show the three from the design; "More account types" reveals the other three |
| N-004 | gap | "Change password", "Forgot password?" (mobile login) and the Activity search icon have no API | Change password shown disabled with "Not available yet"; Forgot password omitted (the web login doesn't show it); search filters loaded rows client-side |
| N-005 | gap | Biller is a dropdown in the design but free text in the API | Fixed list of common Ethiopian billers plus "Other" with free text |
| N-006 | conflict | Banking apps often log out on idle; the brief suggests leaving the app open to watch the token refresh | No idle logout in this version; listed as a production consideration |
| N-007 | conflict | Web register has "Confirm password"; mobile register doesn't | Confirm password on both |
| N-008 | risk | Refresh tokens rotate; two tabs refreshing with the same token would log the user out | Refresh is locked across tabs ([ADR-0005](decisions/0005-token-refresh-strategy.md)) |
| N-009 | risk | Timestamps are UTC without an offset; `new Date()` would read them as local time | One `parseApiDate()` helper; no direct `new Date(apiString)` ([ADR-0007](decisions/0007-money-and-dates.md)) |
| N-010 | risk | The hosted API is shared | Automated tests run against MSW mocks only; a manual live smoke run before release ([ADR-0009](decisions/0009-mock-mode.md)) |
| N-011 | gap | Recipient names can't be looked up (other users' accounts return 403) | Review shows the account number, as in the design; format validated client-side; `ACC_001` shown on the recipient field |
| N-012 | gap | The design shows a Fee row; the API has no fees | Show `ETB 0.00`; total equals amount |
| N-013 | risk | A public, Kifiya-branded banking login could be mistaken for a real one | `noindex` (robots meta tag, `X-Robots-Tag` header and a `robots.txt` that disallows all crawling, [ADR-0010](decisions/0010-content-security-policy.md)), the spec's "Reference client for the Kifiya developer challenge" footer, brand note in README |
| N-014 | gap | "Share receipt" has no API | Web Share API with a text summary; copy-to-clipboard fallback; print stylesheet |
| N-015 | conflict | The web transfer screen shows a success toast; the brief requires a receipt screen, not only a toast | Both: toast plus receipt route |
| N-016 | conflict | The spec says all text meets WCAG AA (4.5:1) in both themes. Measured (`scripts/design-contrast.test.ts`), several token pairs don't. Light: money in on white 3.49, on its badge 3.12; money out on white 4.28, on its badge 3.74; warning banner 3.54; placeholders 3.83; focus ring (accent on white, needs 3:1) 2.80. Dark: links/outline buttons (`primary` on surface) 1.99; `primary` on `primarySoft` 1.50 | By decision the tokens are used exactly as given (only N-001 is overridden). Listed as a known limitation in the README; the test pins which pairs pass and fail, so any token change shows up. Nearest passing light shades, if this is revisited: money in `#197f45`, money out `#c33d23`, warning `#9e5b0e` |
| N-017 | conflict | The dark screens draw the primary button and links in `#17697c` (the dark `primaryHover` token), not dark `primary` `#0f5565`. Sampled from `mobile-LoginDark.png`. White text on `#17697c` is 6.27:1; as link text on the dark surface it is 2.65:1 | Decided (2026-10-01): use the tokens as given, so dark buttons and links are `primary` `#0f5565`. The difference from the screens is recorded here only |
| N-018 | gap | The brief requires a user override of the OS theme, but no screen in the spec shows a theme control | A System / Light / Dark switch styled like the spec's filter pills (`ThemeToggle`), placed on the profile page and, icon-only, in the sidebar |
| N-019 | conflict | The quick-amount chips (+100, +500, +1,000, Max) are drawn about 36px high, but the spec also says every tappable target is at least 44x44px | Chips are 44px high (`h-control-compact`), following the spec's rule over the drawing |
| N-020 | gap | The spec shows no loading, empty or error states (the component sheet's last section, "Filters, badges, feedback, loading, empty", is cut off after the filters and feedback) | Built from the sheet's own patterns: skeletons shaped like the rows they replace, and empty/error states with a tinted disc, a 15/500 title, muted description and one action (`EmptyState`, `ErrorState`) |
| N-021 | gap | The mobile sheets show a grab handle, which usually means swipe-down to close | The handle is decorative; the sheet closes with its Close button, Escape or a tap on the backdrop. Swipe-to-close would need gesture handling and a non-gesture alternative anyway, so it is left out |
| N-022 | gap | The login and register brand panel uses a gradient the tokens don't define. Light matches the balance-card gradient; dark (WebLoginDark) is a flat `#17697c` that lightens to `#2f8397` in the corner, with a dark logo | `bg-auth-panel` in `base.css` with the sampled values. The panel shows from 1024 px; between 768 and 1024 it would leave the form under 280 px, so those widths get the mobile layout |
| N-023 | conflict | The login title is drawn 26px (redline), the type scale's title is 24px | 26px on the auth pages, as drawn; 24px everywhere else |
| N-024 | conflict | Web register draws show/hide on Password but not on Confirm password | Both have it: someone checking a long password shouldn't have to retype it blind |
| N-025 | risk | History pages are fetched by offset (`page`, `size`); a transaction that arrives between two "Load more" clicks shifts every row down one, so the next page repeats the last row already shown | Rows are joined by id and kept once where they first appeared (`flattenHistory`); the count uses the newest page's `totalElements` |
| N-026 | gap | `?tx=` opens a transaction from a link or a reload, but the API can fetch a transaction by id only for transfers and bill payments (`/api/accounts/transfer/{id}`, `/api/accounts/pay-bill/{id}`) | The row is taken from the loaded list when it is there; otherwise the account history is read newest first, 50 rows a request, up to 20 pages. An id not found shows "We couldn't find this transaction." |
| N-027 | gap | The dashboard shows "My accounts" and "Recent activity" without saying how many rows, or which account the activity belongs to when there are several | The first 3 accounts (oldest first) with "View all"; the latest 3 transactions of the first account, named above the rows ("Checking •••• 8057") as drawn, with "View all" to its history |
| N-028 | conflict | The web dashboard puts the balance card and quick actions side by side, but at 768–1023 px the content beside the 260 px sidebar is under 760 px | Side by side from 1024 px; stacked in the mobile order below. The hide/show choice for the balance is remembered on the device |
| N-029 | gap | The design filters history by All / Money in / Money out, but `GET /api/transactions/{accountId}` has no direction parameter | The filter applies to the rows loaded so far; Load more brings in older ones. When nothing matches, the empty state says whether only the loaded rows or the whole history was searched |
| N-030 | gap | "Open an account" shows Savings, Checking and Money market, but the API has three more types, and the design has no descriptions for them | "More account types" reveals Retirement, Fixed-term deposit and Blocked account, each with a one-line description in the same voice; Savings stays preselected, as drawn. After opening, the app goes to the new account with a toast naming it |
| N-031 | gap | The account page shows the full number but no way to copy it; the mobile screen has a share button with no stated behaviour; the Transfer and Pay bill shortcuts don't say how the account is passed on | A copy button beside the number on the card; the share button opens the system share sheet with "My Kifiya Bank account number: …" and falls back to copying. The shortcuts open `/transfer?from=<id>` and `/pay-bill?from=<id>`, which the forms read to preselect the account. An id that isn't one of the user's accounts shows "Page not found" |
